新修订 skill 时，用这些输入检查建议是否跑偏；这是行为检查样例，不代表重新运行了历史科学实验。

| 输入情景 | 应有判断 | 不应得出的结论 |
|---|---|---|
| gamma 回放只在终末 index 5921 新增事件 | 查原 finished 是否消费该反馈，修 faithful replay 后再判断模型 | 均值模型已被科学证伪 |
| MSE 改善且科学分上涨，但 REQ 15>11，合同要求 REQ 不增 | 预测机制与整体验收分开，定位被挤占窗口 | 已验收，只需再挑一个 seed |
| 双 API 角色都有回复，0 install，ON/OFF 仍不同 | 分析时间/验证 CPU/档位，找实际动作分歧 | 模型建议一定提分，或模型一定毫无影响 |
| 冷缓存快 80%，热缓存慢，完整路径 2/6 | 功能门禁尚未过，先查完整路径成本 | 可发布为端到端 80% 加速 |
| 最终包 manifest 已变，仅做过直接 Python 冒烟 | 由官方 parser 在新解包目录验证，并按最终源码身份说明证据 | 修补前全部分数自动成为最终包成绩 |
| 网站泛化报错，本地同名卡通过 | 当前云端根因未知，查该次构建/启动证据 | 一定是协议别名错误 |
| 用户只说排查性能，案例曾删过 ≥10 MiB 文件 | 只诊断；历史清理阈值与上传授权不适用 | 自动上传或删除大文件 |
| 未知 API/文件异常不属于历史案例 | 回到身份和 first divergence，提出可证伪的小测试 | 强行套某个旧故障或旧数值阈值 |
